# design-sync notes — cybersheppard-frontend UI kit

The "design system" is the app's internal UI kit at `frontend-react/src/components/ui/`
(barrel: `index.ts`). This is an **app**, not a published library — no `main`/`module`/
`exports`/`types` in `package.json` and `dist/` is the app build, not a lib entry.

## Build model (how the converter is fed)
- `--entry ./frontend-react/src/components/ui/index.ts` — esbuild bundles the barrel;
  walking up sets `PKG_DIR = frontend-react` (needed so `cssEntry`/`tsconfig`/`srcDir`
  resolve correctly).
- `componentSrcMap` explicitly pins all 15 exports → their src files. Without it discovery
  is `[ZERO_MATCH]`: there is no shipped `.d.ts` tree, so `.d.ts`-based discovery finds 0.
- Real props come from generated `.d.ts` in `frontend-react/types/` (findTypesRoot picks up
  the `types/` dir). Generated by `cfg.buildCmd` via `tsc --emitDeclarationOnly`. Without
  it, every `<Name>Props` collapses to `{ [key: string]: unknown }`.
- CSS: plain Tailwind (default theme, `theme.extend` empty). `cfg.cssEntry` points at
  `ds-ui.generated.css` (37 KB), regenerated by `cfg.buildCmd` via the tailwindcss CLI
  scanning `src/**`. The hash-named `dist/assets/*.css` is NOT used (unstable name).
- `cfg.buildCmd` regenerates BOTH `ds-ui.generated.css` and `types/` — always run it before
  the converter on re-sync (both are gitignored, absent on a fresh clone).
- Deps are clean: components only import `react`, `clsx`, `lucide-react`. lucide-react is
  inlined into the bundle; preview `.tsx` may import lucide icons (bundled at preview compile).

## Render-check browser
- playwright **1.59.0** pins chromium build **1217**, which is already cached in
  `~/.cache/ms-playwright/`. Installed into `.ds-sync/` with
  `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`. Newer playwright (repo has none) pins other builds.

## Component scope
- Authored rich previews (7): Button, Badge, Card, Table, Input, Select, StatCard — all
  graded good. Table uses `overrides.Table.cardMode = "column"` (wide data table).
- Floor cards (8): CardHeader, CardSection, EmptyState, PageHeader, SeverityBadge,
  StatusBadge, StatsGrid, Modal — importable + functional, no rich preview.

## Known render warns
- `[RENDER_THIN]` on **StatCard** appears only when its preview is NOT authored (floor
  render shows just the name). With `previews/StatCard.tsx` present it renders fully — not a
  standing warn.

## Modal — deliberately on the floor card
- `Modal` renders `position: fixed inset-0` and returns `null` when closed. With `isOpen`
  the dialog mounts (its text IS in the DOM) but the story root collapses to `maxHeight: 0`,
  so both the render-check and per-cell capture screenshot blank (`bad`/`thin`). `cardMode:
  single` + a viewport did not fix it (fixed element is out of the root's box).
- Decision: ship Modal as a floor card. It's fully importable and its `.d.ts`
  (isOpen/onClose/title/subtitle/footer/size) + `.prompt.md` document the API.
- To author it later, the preview would need a wrapper that gives the fixed overlay a
  measurable box (or a capture mode that screenshots the full viewport, not the root).

## Re-sync risks
- `types/` and `ds-ui.generated.css` are generated (gitignored) — a re-sync MUST run
  `cfg.buildCmd` first or props go empty / CSS goes missing.
- `componentSrcMap` is a full enumeration (15 entries). If a component is added/removed in
  `src/components/ui/`, update it AND the barrel — discovery is driven by this map, not by
  scanning, because there is no shipped `.d.ts` tree.
- Preview content is realistic SIEM domain data authored inline (hosts, CVEs, severities) —
  not tied to any repo fixture, so it won't rot from upstream code changes.
- Tailwind default theme only; if the app later adds `theme.extend` tokens, regenerate the
  CSS (buildCmd already does) and consider adding a tokens surface.
